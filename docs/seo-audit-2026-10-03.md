# SEO and speed audit, 3 October 2026

Scope: every HTML page in `iliasabk/regime-legal` (privacy home, `/app/`, `/why-hard-streak/`, `/vs-soft-habit-apps/`) plus crawl files. Measured on the live GitHub Pages site before edits, then again on a local server of this branch after edits.

Tooling: manual review of titles, meta, canonicals, social tags, JSON-LD, headings, alt text, and links. Asset bytes from the files on disk. Lighthouse 12, mobile, simulated throttling (Moto G Power profile: 412x823, DPR 1.75). Live response headers via curl. App Store facts via the public iTunes lookup for id 6805791943 on 3 October 2026 (live version 1.1.0).

## What was wrong, and what changed

### Crawl files

- `robots.txt` returned 404. Added an allow-all file that points at the sitemap.
- `sitemap.xml` returned 404. Added one with the four existing URLs and the four new guides. `lastmod` is 2026-10-03.
- No custom 404. Added `404.html` (`noindex`, same visual system, links to every real page). GitHub Pages serves that file for unknown paths. A local Python server does not, so the 404 behavior was checked by confirming the file and the links, not by a GitHub status code.
- `/favicon.ico` returned 404 and Lighthouse logged a console error on every page that had no icon link (best-practices 96). Added a 32px `favicon.ico` at the site root and icon links on every page.

### Canonicals pointed at a parked domain

`/why-hard-streak/` and `/vs-soft-habit-apps/` set canonical and `og:url` to `https://regime.is-a.dev/...`. That host answered 302 to `https://is-a.dev/available?d=regime` on 3 October 2026. The pages themselves live on `https://iliasabk.github.io/regime-legal/`. Canonical and Open Graph URLs now match the GitHub Pages URLs. The visible "Canonical:" line at the bottom of those two articles was updated to the same URL. Privacy-policy and terms text were not edited.

### Social tags and structured data

- Privacy, hard-streak, and vs-soft pages had no `og:image`, no image dimensions, and no Twitter card. All pages now use `app/assets/og-image.jpg` (48,165 bytes) instead of `og-image.png` (322,493 bytes). The PNG is still in the repo.
- `/app/` JSON-LD had `"screenshot": []`. It now lists the three real screenshot URLs, plus the 512px icon.
- Homepage JSON-LD offered only a $0 price. The visible privacy page already lists Weekly $4.99, Yearly $29.99, and Lifetime $49.99. The schema now includes those three offers plus the $0 download. The $0 offer description is: "Optional Pro plans: weekly, yearly (7-day free trial) or lifetime." `isAccessibleForFree` is true, because Pro is optional. `operatingSystem` is `iOS`.
- Both existing FAQ sections were real and had no `FAQPage` schema. Schema was added from the visible questions and answers, without rewriting them.
- Each new guide has its own `WebPage`, `MobileApplication`, and `FAQPage` graph. Download URLs in that schema use the page's `ct` tag.

### `/app/` speed and accuracy

Lighthouse's LCP element was the first phone screenshot, which was `loading="lazy"` and only partly in the first viewport (top at 733px of an 823px viewport). It also downloaded the 780px WebP because the only smaller candidate was 390px, and 280 CSS pixels at DPR 1.75 needs about 490 pixels. That audit estimated 74 KiB of oversized-image waste and 105 KiB of image-delivery waste. Transfer of the three `@2x` WebPs was 48.9 + 46.0 + 29.1 KiB.

Fixes:

- Generated a 520px WebP for each screenshot (26.2, 24.8, and 15.4 KiB on disk). The `<picture>` source now offers 390, 520, and 780. Mobile Lighthouse selected the 520px files (26.3, 25.0, and 15.6 KiB transferred). `uses-responsive-images` went from score 0 to score 1.
- Removed lazy-load from that first screenshot, set `fetchpriority="high"`, and preloaded it with the same `srcset` and `sizes`. LCP went from 1.7 s to 1.4 s. The lazy-load and LCP-discovery audits cleared.
- The Fazier badge had `width="120"` and no height (rendered 120x51), so it failed the explicit-dimensions audit. It now has `width="120"` `height="51"`, `loading="lazy"`, and `decoding="async"`. It was not removed or moved. The double slash in its badge URL is unchanged. After the change it is no longer in the initial transfer list.
- Footer text `#6e6e73` on `#0e0e10` was contrast 3.80:1. `--dim` is now `#8e8e93` (about 5.9:1). Feature kickers used `#e3272e` at 4.22:1. `--accent` is now `#ee5a5a`.
- The third screenshot is the day-complete / share screen (filename `screenshot-04-day-complete`). Its alt text and the section next to it described a seven-day grid. Alt text now describes the day-complete screen. The section states the weekly review, hold-to-commit, and the DAY COMPLETE stamp.
- The app footer now links to the two existing guides and the four new ones. Existing `ct=landing` links were not retagged.

### Other pages

- The red rule line `#c81e1e` on `#0b0b0c` was contrast 3.42:1 (the accessibility failure on `/`, `/why-hard-streak/`, and `/vs-soft-habit-apps/`). Rule text is now `#ee5a5a` (about 5.9:1). Button backgrounds stay `#c81e1e`, where white text is 5.74:1.

## What remains, and why

- **Cache lifetime.** GitHub Pages sends `cache-control: max-age=600`. Lighthouse still flags that on `/app/`. This repo cannot set a longer cache header without leaving GitHub Pages.
- **Fazier badge.** It stays in the `/app/` footer until at least 2 November 2026. It is a third-party request once the footer is reached. It is now lazy and sized, so it is not part of LCP.
- **PNG screenshot fallbacks.** The `@2x` PNGs are 463 to 577 KiB. Chrome and current Safari use the WebP `<source>` and do not download them. They stay for older clients.
- **Further image compression.** After the 520px WebP cut, Lighthouse's image-delivery insight still estimates about 36 KiB on the two heavier screenshots. `uses-responsive-images` already passes and the performance score is 100. Another quality cut would blur UI text, so it was not taken.
- **`countriesSupported: "US"`** on the existing app schema was left in place. The lookup was US-only, and other storefronts were not verified.
- **Three existing em dashes** on `/app/` (the title and two feature sentences) were left. They are old copy. New copy does not use em dashes.
- **Rank day counts** visible in a screenshot were not published. OCR of the lower ladder was incomplete, so the pages only repeat the on-screen line that the eight earned ranks run from RECRUIT to IMMORTAL.
- **Search Console.** Nothing in the repo can submit the sitemap. After deploy, submit `https://iliasabk.github.io/regime-legal/sitemap.xml` in Search Console if that property exists.
